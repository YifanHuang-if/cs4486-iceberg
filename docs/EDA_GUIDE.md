# 第3–4步：数据检查与基础EDA

状态：已用课程项目的原始数据运行。尚未建立模型、产生预测成绩或确定正式验证划分。

## 运行方式

1. 每位组员自行接受Kaggle规则并下载数据。
2. 解压后找到真正的 `train.json`、`test.json`、`sample_submission.csv`，放入 `data/raw/`。压缩包内部带有 `data/processed/` 目录，不要把外层文件夹误当作数据文件。
3. 在VS Code中打开整个仓库，在终端运行以下命令。Notebook需要选择同一个Python解释器。

```bash
python -m pip install -r requirements-eda.txt
python -m src.eda --data-dir data/raw
```

也可以打开 `notebooks/01_eda.ipynb`，从上到下运行。Notebook与命令行调用同一份分析代码。

`requirements-eda.txt` 是本阶段经过实际运行的依赖版本，供小组检查后采用。训练所用的PyTorch、CUDA和GPU环境另行确定。

## 代码做了什么

- 逐条读取JSON，不把约1.5 GB的测试JSON整体展开在内存中。
- 检查必需字段、唯一ID、训练标签、每个通道的5625个有限数值。
- 保留原始dB数值，不除以255，不在全量数据上拟合标准化参数。
- 把缺失角度记为缺失；此阶段不填补、不生成训练特征。
- 用两个通道的数值指纹检查完全重复图像；这不等于近似图像检测。
- 统计类别、角度缺失、精确相同角度组及标签构成。
- 检查提交示例的列名、概率范围、ID集合和顺序。
- 保存原始文件SHA-256与运行环境，方便组员核对数据版本。

图像指纹使用按顺序拼接的两个通道、小端float64字节和SHA-256。图像展示使用样例像素的共享1%–99%分位色阶，仅改变显示效果，不修改数据。

## 本次数据的观察

| 项目 | 结果 |
|---|---:|
| 训练样本 | 1,604 |
| 测试样本 | 8,424 |
| 船 / 冰山 | 851 / 753 |
| 训练集缺失角度 | 133（8.29%） |
| 测试集缺失角度 | 0 |
| 训练集重复角度组 | 217组，涉及810条样本 |
| 重复角度组中只有一种标签的组 | 211 |
| 重复角度组中混合标签的组 | 6 |

133条缺失角度记录全部属于船。这个关联可能让模型依赖缺失标记，而测试集并没有对应缺失样本。因此应比较有无缺失标记的方案，并分别报告已知角度和缺失角度子集结果。

相同角度组中标签高度一致，支持进一步考虑分组验证，但角度并不是真实场景ID。不能仅凭该统计就证明随机划分存在泄漏，也不能宣称按角度分组已经消除了全部泄漏。

未发现重复ID或两个通道数值完全相同的重复图像，包括训练集与测试集之间。近似图像排查尚未完成。提交示例中的0.5都是占位概率，不是训练结果。
